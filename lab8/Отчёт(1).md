## Часть 1: Deploy в облаке

Тут кратко описано: фронтенд (Next.js) на Vercel, бэкенд (FastAPI) контейнеризируется, публикуется в реестр и запускается в облаке; данные хранятся в Managed PostgreSQL.  

Ключевые шаги, выполненные в работе:

- Подготовлен Dockerfile для бэкенда.
- Добавлены конфигурационные переменные через `.env` / GitHub Secrets.
- Фронтенд настроен для использования переменной `NEXT_PUBLIC_API_URL`.

Проверки локально:

```bash
# backend
pip install -r backend/requirements.txt
uvicorn backend.main:app --reload
curl http://localhost:8000/health
```

## Часть 2: CI/CD

Описание pipeline: автоматические проверки при PR, тесты, сборка фронтенда и деплой на Vercel при push в `main`, сборка Docker-образа бэкенда и публикация в Yandex Container Registry, обновление Cloud Run.

Примеры workflow расположены в `.github/workflows/`:

- `deploy.yml` — основной placeholder для CI/CD
- `pr-checks.yml` — проверки для Pull Request (lint, тесты)

Важные секреты (добавить в GitHub Secrets): `VERCEL_TOKEN`, `YC_SA_KEY_JSON`, `YC_REGISTRY_ID`, `DB_URL`.

## Ответы на вопросы

- Почему Vercel подходит для Next.js? — нативная поддержка и автоматический билд.  
- Почему контейнер для бэкенда? — изоляция окружения и переносимость.  
- Почему БД отдельная? — сохранность данных независимо от аппликейшн-контейнера.
