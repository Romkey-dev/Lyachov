## Часть 1: ETL на Python

### Описание

Реализован класс `SalesETLPipeline` с методами:

- `extract()` — загрузка данных из CSV;
- `transform()` — очистка, фильтрация, преобразование типов;
- `aggregate()` — группировка по категории и месяцу;
- `load_to_sqlite()` — запись очищенных и агрегированных данных в SQLite;
- `visualize()` — построение и сохранение трёх графиков.

### Технологии

- Python 3
- pandas
- numpy
- sqlalchemy
- matplotlib
- seaborn
- SQLite

### Ключевые этапы реализации

1. **Extract**
   - Загружен файл `data/sales.csv`.
   - Обработаны ошибки: файл не найден, пустой файл.
   - Выведены типы колонок и базовая статистика.

2. **Transform**
   - Удалены дубликаты.
   - Заполнены пропуски: числовые поля медианой, текстовые — `Unknown`.
   - Отфильтрованы строки с `quantity <= 0` и `price_per_unit <= 0`.
   - Преобразованы типы: `order_date` → `datetime`, `quantity` и `price_per_unit` → числовые.
   - Добавлены поля `total_amount` и `month_year`.

3. **Aggregate**
   - Сгруппировано по `category` и `month_year`.
   - Рассчитаны метрики: `total_quantity`, `total_revenue`, `avg_price`, `order_count`.

4. **Load**
   - Сохранён результат в таблицы `sales_cleaned` и `sales_aggregated`.
   - Проверено наличие таблиц в базе.

5. **Visualize**
   - Построены графики:
     - выручка по категориям;
     - динамика выручки по месяцам;
     - доля категорий в общей выручке.
   - Графики сохранены в `lab1501_etl/report/`.

### Файл реализации
- `lab1501_etl/etl_pipeline.py`

## Часть 2: Apache Kafka

### Описание

Реализована потоковая архитектура с Kafka-продюсером и консюмером.

### Технологии

- Docker Compose
- Apache Kafka
- kafka-python
- Python 3

### Ключевые этапы реализации

1. **Kafka инфраструктура**
   - Конфигурация `docker-compose.yml` запускает сервисы:
     - `zookeeper`
     - `kafka`
     - `kafka-ui`
   - Порт Kafka: `9092`, Kafka UI: `8080`.

2. **Producer**
   - Файл: `lab1502_kafka/producer.py`.
   - Подключается к Kafka с JSON-сериализацией.
   - Отправляет события заказов в топик `orders`.
   - Использует ключ `customer_id` для партиционирования.
   - Включены `acks='all'` и `retries=3`.

3. **Consumer**
   - Файл: `lab1502_kafka/consumer.py`.
   - Подключается к Kafka и читает события с `auto_offset_reset='earliest'`.
   - Обновляет статистику:
     - общее число заказов;
     - общую выручку;
     - количество заказов по категориям;
     - количество заказов по городам;
     - последние 10 заказов.

## Ответы на вопросы

### Какие аномалии и пропуски были обнаружены?

- Пропуски в полях `product_name`, `category`, `customer_name`, `customer_city`.
- Пустая строка с отсутствующими данными товара и клиента.
- Отрицательное значение `quantity` в одной строке.
- Дубликат заказа `1010`.

### Как они обработаны?

- Текстовые пропуски заменены на `Unknown`.
- Числовые пропуски заполнены медианой.
- Удалены строки с `quantity <= 0` или `price_per_unit <= 0`.
- Дубликаты удалены методом `drop_duplicates()`.

### В чём разница между ETL и ELT?

- ETL: данные сначала извлекаются, затем трансформируются, и только после этого загружаются.
- ELT: данные сначала загружаются в хранилище, а уже там выполняется трансформация.
- Для данной задачи ETL предпочтительнее, так как требуется предварительная очистка и контроль качества данных перед записью.

### Почему данные не загружают напрямую в базу без очистки?

- Неочищенные данные могут привести к неверным аналитическим результатам.
- Аномалии и дубликаты нарушают целостность и искажают отчёты.
- Очистка повышает надёжность и читаемость данных.

### Какие ещё трансформации могли бы быть полезны?

- нормализация категорий и наименований товаров;
- вычисление прибыли или маржи;
- выделение региона на основе города;
- агрегация по клиентам и способам оплаты;
- детекция выбросов и сезонных аномалий.
