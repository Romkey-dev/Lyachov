## Цель работы
Построить ETL-пайплайн для загрузки данных из CSV, очистки, агрегации и сохранения результата в SQLite, а также визуализировать ключевые метрики.

## Структура проекта
- `data/sales.csv` — исходные данные о продажах.
- `etl_pipeline.py` — основной скрипт ETL.
- `sales.db` — SQLite база данных (создаётся при запуске).
- `report/category_revenue.png` — график выручки по категориям.
- `report/monthly_trend.png` — график динамики продаж.
- `report/category_share.png` — круговая диаграмма доли категорий.

## Выполненные этапы

### 1. Extract
- Загружен CSV-файл.
- Обработаны ошибки: файл не найден, пустой файл.
- Выведена информация о количестве строк и типах колонок.

### 2. Transform
- Удалены дубликаты по всем колонкам.
- Пропуски в числовых колонках заполнены медианой.
- Пропуски в текстовых колонках заполнены строкой `Unknown`.
- Удалены строки с `quantity <= 0` и `price_per_unit <= 0`.
- Преобразованы типы: `order_date` → datetime, `quantity` и `price_per_unit` → числовые значения.
- Добавлена колонка `total_amount` и `month_year`.

### 3. Aggregate
- Выполнена группировка по `category` и `month_year`.
- Рассчитаны: `total_quantity`, `total_revenue`, `avg_price`, `order_count`.

### 4. Load
- Сохранены очищенные данные в таблицу `sales_cleaned`.
- Сохранены агрегированные данные в таблицу `sales_aggregated`.
- Проверено наличие таблиц в SQLite.

### 5. Visualize
- Построены 3 графика:
  - выручка по категориям,
  - динамика выручки по месяцам,
  - доля категорий в общей выручке.

## Результаты
- Очищенные данные сохранились в `sales_cleaned`.
- Агрегированные результаты сохранились в `sales_aggregated`.
- Графики сохранены в папке `report`.

## Ответы на вопросы

### Какие аномалии и пропуски были обнаружены?
- Пропущены значения `product_name`, `category`, `customer_name` и `customer_city`.
- В одной строке отсутствовали товар и данные клиента.
- Были отрицательные значения `quantity` и дубликат заказа `1010`.

### Как их обработал?
- Текстовые пропуски заменены на `Unknown`.
- Числовые пропуски заполнены медианой.
- Аномальные строки удалены, так как отрицательное количество и цена могут исказить аналитику.

### В чём разница между ETL и ELT?
- ETL: сначала извлечение, затем трансформация, потом загрузка.
- ELT: сначала загрузка, затем трансформация уже в хранилище.
- Для этой задачи ETL подходит лучше, потому что нужна предварительная очистка перед записью в базу.

### Почему данные не загружают напрямую без очистки?
- Неочищенные данные могут разрушить отчёты и привести к неверным метрикам.
- Плохие данные усложняют агрегацию, анализ и нарушают целостность базы.

### Какие ещё трансформации полезны?
- Нормализация названий продуктов и категорий.
- Выделение региона по городу.
- Расчёт среднего чека на клиента.
- Детекция выбросов по цене и объёму заказа.
