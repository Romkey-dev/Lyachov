# Часть 2: Выбор низкокодового инструмента

## Выбранный инструмент
- **AppMaster.io**

## Причины выбора
- Поддержка быстрой генерации backend и frontend без написания кода.
- Возможность строить бизнес-логику, базы данных и API в визуальном конструкторе.
- Альтернатива Airtable, подходящая для разработки приложений с собственной логикой.

## Концепция приложения

### Схема данных
- Таблица `Клиенты`
- Таблица `Товары`
- Таблица `Заказы`
- Таблица `Позиции заказа`

### Основные поля
- `Клиенты`: имя, email, телефон, статус.
- `Товары`: наименование, категория, цена, остаток.
- `Заказы`: клиент, дата, статус, способ оплаты, общая сумма.
- `Позиции заказа`: заказ, товар, количество, цена, сумма позиции.

### Визуальные компоненты
- Форма создания заказа.
- Таблица заказов с фильтрацией по статусу.
- Страница со списком товаров и остатком на складе.

## Что сделано в рамках отчёта
- Подготовлен план архитектуры данных.
- Описаны связи между таблицами.
- Дано сравнение low-code-подхода с традиционной разработкой.

## Ограничения
- Работа с AppMaster.io выполнена концептуально, без доступа к реальному приложению.
- Для полного выполнения требуется учетная запись и рабочая база на платформе.
