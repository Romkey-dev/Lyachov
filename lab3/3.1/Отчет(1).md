## 1. Цель работы
Получить практические навыки создания нативного Android-приложения на Kotlin с использованием современного декларативного подхода Jetpack Compose, архитектурных компонентов Jetpack (ViewModel, StateFlow) и локальной базы данных Room.

## 2. Структура проекта
Проект реализован по архитектуре MVVM (Model-View-ViewModel):
- `data/` — модель данных `Note`, DAO `NoteDao`, база `NoteDatabase` и репозиторий `NoteRepository`.
- `ui/` — ViewModel `NotesViewModel`, фабрика `NotesViewModelFactory`, экран списка `NotesScreen.kt` и экран редактирования `AddEditNoteScreen.kt`.
- `MainActivity.kt` — точка входа, привязка ViewModel и Compose UI.
- `ui/theme` — тема приложения.

## 3. Реализация задания
### 3.1. Модель данных
В классе `Note.kt` добавлено поле `createdAt` типа `Long` для хранения времени создания заметки.

```kotlin
@Entity(tableName = "notes")
data class Note(
    @PrimaryKey(autoGenerate = true)
    val id: Int = 0,
    val title: String,
    val content: String,
    val createdAt: Long = System.currentTimeMillis()
)
```

### 3.2. DAO и репозиторий
Реализованы методы для работы с Room:
- `getAllNotes()` — чтение списка заметок как `Flow<List<Note>>`;
- `insertNote()` — добавление заметки;
- `updateNote()` — обновление заметки;
- `deleteNote()` — удаление заметки;
- `getNoteById()` — получение заметки по `id`.

### 3.3. ViewModel
`NotesViewModel` управляет состоянием UI и бизнес-логикой:
- подписка на `repository.allNotes`;
- хранение текущей заметки и текста для ввода `title`/`content`;
- сохранение заметки (`insert`/`update`);
- удаление заметки;
- сброс черновика при переходе на экран создания.

### 3.4. UI на Jetpack Compose
Реализованы экраны:
- `NotesScreen.kt` — список заметок с возможностью редактирования и удаления;
- `AddEditNoteScreen.kt` — экран создания и редактирования заметки;
- форматирование даты создания заметки в карточке заметки.

### 3.5. Навигация
В корневом Compose-экранe используется `NavHost` с маршрутами:
- `notes_list` — главный экран списка;
- `edit_note` — экран создания/редактирования заметки.

## 4. Ответы на вопросы
**1. В чем преимущество использования Flow и StateFlow перед обычными списками?**
Flow обеспечивает реактивное обновление данных при изменении базы, а StateFlow хранит последнее состояние для UI. Это позволяет Compose автоматически перерисовывать экран при изменении списка заметок.

**2. Почему ViewModel не уничтожается при повороте экрана и как это влияет на UX?**
ViewModel сохраняется при смене конфигурации, поэтому данные и состояние экрана не теряются. Это улучшает UX, потому что пользователь не теряет введенный текст и список заметок не перезагружается заново.

**3. Какие преимущества дает использование Room по сравнению с прямым использованием SQLite?**
Room предоставляет проверку SQL-запросов на этапе компиляции, уменьшает шаблонный код и обеспечивает удобную интеграцию с Flow и Coroutines.
